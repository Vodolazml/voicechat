# Private VoiceChat

Приватное desktop-приложение для общения в закрытых пространствах. Цель проекта: сначала собрать понятную программу с пространствами, каналами, подключением к каналам и безопасной основой, затем отдельными этапами добавить настоящий голосовой чат, демонстрацию экрана и текстовый чат.

Весь проект ведем в UTF-8. Интерфейс приложения будет полностью на русском языке.

## Быстрый запуск

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt

$bytes = New-Object byte[] 32
[Security.Cryptography.RandomNumberGenerator]::Fill($bytes)
$env:VOICECHAT_SECRET_KEY=[Convert]::ToBase64String($bytes)
$env:VOICECHAT_ENVIRONMENT="development"
python -m uvicorn app.server.main:app --reload --host 127.0.0.1 --port 8765
```

В другом терминале:

```powershell
.\.venv\Scripts\Activate.ps1
python -m app.client.main
```

Первый вход: `admin` и одноразовый пароль, который сервер печатает в консоль при первом запуске. Его сразу нужно сменить.

**Запуск на своём сервере с доменом:** [docs/DEPLOY.md](docs/DEPLOY.md) — одна команда `sudo deploy/install.sh <домен> <email>`.

## Текущий этап

Сейчас реализуется первая рабочая основа:

- правила кодировки и переносов строк;
- зависимости Python;
- Dockerfile и Docker Compose для локальной разработки и будущей загрузки на сервер;
- backend с учетными записями, правами, пространствами, каналами и подключением к голосовому каналу как состоянием;
- PySide6-клиент с русским интерфейсом, входом, сменой временного пароля и Discord-подобной компоновкой.
- рабочий голосовой MVP: микрофон клиента отправляет аудио на сервер по WebSocket, сервер ретранслирует звук участникам того же канала.

Текущий голосовой слой использует raw PCM 16 kHz mono. Это удобно для первого рабочего прототипа, но дальше его стоит заменить или дополнить Opus/WebRTC, echo cancellation, noise suppression и отдельным media-сервисом.

## Безопасность

- только HTTPS/WSS: клиент не подключается к удалённому серверу по `http://`, а к медиасерверу по `ws://`;
- сервер в production не стартует с опубликованными или слабыми секретами, `/docs` выключен;
- короткие access-токены (15 минут) и refresh-токены, которые меняются при каждом обновлении; повтор старого токена завершает все сессии;
- вход по одноразовым приглашениям, список устройств и выход на любом из них;
- голос и демонстрация экрана шифруются на клиентах (E2EE через LiveKit), медиа-ключи раздаются X25519/HKDF/AES-GCM конвертами.

Подробности и схема развёртывания: [docs/DEPLOY.md](docs/DEPLOY.md).

Для раздачи клиента без ручного ввода адреса используйте `client_config.example.json`: скопируйте его в `client_config.json`, впишите `https://chat.<домен>` и оставьте `lock_server_url: true`.

## Порядок разработки

1. Основа программы: GUI, пространства, каналы, подключение/отключение от каналов, роли и permissions.
2. Голосовой чат.
3. Демонстрация экрана.
4. Текстовый чат.
5. Установщик, подпись обновлений и production-процессы.
