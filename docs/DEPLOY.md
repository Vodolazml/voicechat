# Запуск сервера на своём домене

Сервер ставится одной командой на чистую Ubuntu 24.04. После установки клиенты подключаются к `https://chat.<домен>`. Звонки и демонстрация экрана идут через LiveKit на `wss://rtc.<домен>` и шифруются на клиентах (E2EE).

## Что понадобится

- Домен, например `example.org`, и доступ к его DNS.
- VPS: Ubuntu 24.04, 2 vCPU, 4 ГБ RAM, публичный IPv4, канал от 100 Мбит/с. Этого хватит для 10–15 человек.
- E-mail для Let's Encrypt (туда приходят предупреждения о сертификатах).

## 1. DNS

У регистратора домена создайте две A-записи на IP сервера:

| Имя | Тип | Значение |
| --- | --- | --- |
| `chat` | A | IP сервера |
| `rtc` | A | IP сервера |

Подождите, пока записи начнут резолвиться (`ping chat.example.org` показывает IP сервера). Обычно это 5–30 минут.

## 2. Установка

```bash
ssh root@<IP сервера>
git clone https://github.com/Vodolazml/voicechat.git /opt/voicechat
cd /opt/voicechat
sudo deploy/install.sh example.org you@example.org
```

Скрипт:

- проверяет DNS;
- ставит Docker и включает автоматические обновления безопасности Ubuntu;
- настраивает firewall: открыты только SSH, 80/443 TCP, 443 UDP, 7881 TCP, 3478 UDP и 50000–60000 UDP;
- генерирует все секреты в `.env.production` (права 600, в git не попадает);
- поднимает PostgreSQL, API, LiveKit и Caddy (сертификаты Let's Encrypt получает и продлевает сам);
- включает ночной бэкап базы в `/var/backups/voicechat` (хранится 14 дней);
- печатает одноразовый пароль владельца `admin`.

Повторный запуск безопасен: секреты сохраняются, сервисы пересобираются и перезапускаются.

## 3. Первый вход

1. В клиенте укажите сервер `https://chat.example.org`.
2. Войдите как `admin` с паролем из вывода скрипта. Программа сразу попросит задать свой пароль.
3. Друзей приглашайте кодом приглашения: код одноразовый, живёт 24 часа, друг сам придумывает пароль. Администратор чужих паролей не знает.

Если вывод скрипта потерян, пароль можно найти в логе первого запуска: `docker compose -f docker-compose.prod.yml logs api | grep "one-time password"`.

## Как устроена безопасность

- Весь трафик идёт по HTTPS/WSS. Клиент отказывается подключаться к удалённому серверу по `http://` и к медиасерверу по `ws://`.
- Сервер не стартует в production с паролями и ключами, которые когда-либо публиковались в репозитории, с `ws://` для LiveKit и с коротким секретом LiveKit.
- Access-токен живёт 15 минут. Refresh-токен меняется при каждом обновлении; если кто-то предъявит старый (украденный) токен, все сессии пользователя завершаются.
- Смена пароля завершает сессии на всех устройствах. В настройках видно список устройств и можно выйти на любом из них.
- Владелец сервера защищён: другие администраторы не могут его заблокировать или сбросить ему пароль.
- При переходе в другой канал и при пропаже клиента сервер выгоняет его из медиакомнаты, поэтому «невидимых слушателей» нет.
- Документация API (`/docs`) в production выключена.
- API, LiveKit и PostgreSQL слушают только локальный интерфейс или закрыты firewall; наружу смотрит только Caddy и медиапорты LiveKit.

## Обслуживание

```bash
cd /opt/voicechat
docker compose -f docker-compose.prod.yml ps          # состояние
docker compose -f docker-compose.prod.yml logs -f api # логи
git pull && sudo deploy/install.sh example.org you@example.org  # обновление сервера
```

Восстановление из бэкапа:

```bash
gunzip -c /var/backups/voicechat/voicechat-2026-11-05.sql.gz | \
  docker compose -f docker-compose.prod.yml exec -T postgres psql -U voicechat voicechat
```

### Публикация новой версии клиента

1. Соберите и подпишите установщик (`deploy/build_client.ps1 -ServerUrl https://chat.example.org`).
2. Положите `PrivateVoiceChat-<версия>-setup.exe` и `.release.json` в `/opt/voicechat/downloads/`.
3. `python3 deploy/configure.py example.org --installer PrivateVoiceChat-<версия>-setup.exe`
4. `docker compose -f docker-compose.prod.yml up -d api`

Ключ подписи релизов (`release-signing.key`) храните только у себя: без него клиенты не примут обновление.

## Если что-то не работает

- **Сертификат не выдаётся**: проверьте, что `chat.` и `rtc.` резолвятся в IP сервера и что порт 80 открыт у хостера (некоторые VPS имеют отдельный firewall в панели).
- **Голос не проходит у кого-то одного**: у хостера должны быть открыты 50000–60000 UDP, 7881 TCP и 3478 UDP.
- **База от старой версии сервера**: сервер версии 0.3 использует миграции и PostgreSQL; старая SQLite-база не переносится, начните с чистой.
