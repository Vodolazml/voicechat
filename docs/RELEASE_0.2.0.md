# Версия 0.2.0: WebRTC и исправления надёжности

Это выпуск для совместного тестирования. Он заменяет медиапуть версии 0.1.x; всем участникам нужно обновить клиент. Проверки на локальном стенде не являются гарантией 4K/60 на любом ПК или безопасности HTTP-развёртывания.

## Изменения

- Голос: LiveKit / WebRTC / Opus, E2EE с индивидуальными ключами участников; отдельные ограниченные очереди и смешивание на выходе. Громкость применяется при воспроизведении, подсветка отражает вклад участника в выходной микс.
- Шум и эхо: WebRTC AudioProcessingModule; порог активности сохранён отдельно от обработки шума.
- Видео: LiveKit / WebRTC / H.264, отдельный поток захвата, 4K и цель 60 FPS, ограниченная очередь последних декодированных кадров. Курсор отображается. Просмотр может выбирать слой simulcast; ограничение FPS просмотра локальное и не гарантирует уменьшение входящего трафика.
- Повторный вход: исправлена смена ID ключа; повторная публикация ключей и идентичностей; независимое обслуживание активного канала; обновление авторизации; восстановление медиасоединений.
- Mute/deafen: возврат предыдущего mute после deafen; очистка накопленного микрофонного звука при mute; проверка mute перед передачей.
- Смена устройств закрывает старые потоки перед созданием новых, предусмотрен возврат к прежним устройствам и повторная попытка восстановления остановившегося потока.
- Опрос участников и ping вынесен из GUI. Административные команды и некоторые переходы по каналам пока выполняют синхронные API-запросы.
- Администрирование: список пользователей, генерация временного пароля на 24 часа, сброс и блокировка; сервер запрещает обычную работу до смены пароля. Назначение администратора требует отдельного права.
- «Запомнить меня»: refresh-токен на 30 дней под DPAPI вместо сохранения постоянного пароля; смена пароля и блокировка отзывают сессию. Приватная E2EE-идентичность также сохраняется под DPAPI на Windows.
- Обновления: Ed25519-подпись версии, URL и SHA-256; доверенный публичный ключ включён в клиент. Первый переход с 0.1.x ещё использует прежний механизм доверия старого клиента: предпочтительна ручная проверка хэша нового установщика.
- Docker: отдельные серверные зависимости, непривилегированный API, healthcheck, LiveKit, подготовка прав существующего тома.

## Проверка

Проверены реальным локальным LiveKit: доставка и декодирование E2EE H.264, доставка Opus и повторный вход с новым ключом. В контейнере API проверены login, обязательная смена пароля, refresh, генерация пользователя, вход в канал и выдача медиатокена.

Тесты с настоящим медиасервером запускаются явно:

```powershell
$env:VOICECHAT_TEST_LIVEKIT_URL="ws://127.0.0.1:7880"
pytest -q
```

Этот стенд ожидает локальный LiveKit в режиме dev, изолированный от интернета. Для VPS dev-режим запрещён.

## Ограничения перед постоянным использованием

- IP-конфигурация использует HTTP/WS. Пароли, токены и обмен ключами требуют TLS перед приватным использованием. E2EE-медиа не исправляет отсутствие аутентификации канала обмена ключами.
- E2EE ещё не имеет независимой проверки личностей/отпечатков и защиты от активной подмены ключей скомпрометированным сервером. Не заявляется соответствие всем стандартам или завершённый криптографический аудит.
- Не выполнен длительный прогон 4K/60 на GPU пользователя и VPS. Пункт 60 FPS задаёт цель; реальная частота зависит от захвата, кодировщика, декодировщика и сети. Аппаратный кодировщик выбирает SDK при наличии поддержки; возможен программный fallback.
- Полный матричный прогон Bluetooth, USB, sleep/wake, потерь сети и десяти реальных клиентов ещё нужен. Смена устройств может сопровождаться короткой паузой.
- TURN/TLS для сетей, блокирующих обычный UDP/TCP медиатрафик, в IP-конфигурацию не включён.
- Установщик не имеет Authenticode-сертификата; подпись обновлений проверяется приложением. Рабочий путь обновления запускает установщик с подтверждением, а не полностью скрытую замену программы в фоне.
- Старый расширенный updater ещё требует отдельной проверки автоматического отката установленного приложения. Для выпуска используется обычный подписанный EXE.

## Ключ подписи

`release-signing.key` существует только на компьютере сборки. Он исключён из Git и Docker-контекста. Не загружать его на VPS и не передавать участникам. Нужна отдельная защищённая резервная копия. Утрата ключа потребует процедуры смены доверенного ключа в клиентах.
