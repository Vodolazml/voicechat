# Аудит безопасности

Дата: 2026-08-17

## Закрыто в текущей версии

- Пароли хэшируются через Argon2.
- Access-токены подписываются HMAC-SHA256, имеют срок жизни и становятся недействительными после смены пароля.
- REST-запросы ограничены по размеру, входы и смена пароля защищены rate limit.
- Сервер требует явный `VOICECHAT_SECRET_KEY` и не стартует с примерным dev-секретом.
- HTTP-ответы получают базовые security headers.
- CORS отключен по умолчанию и включается только явным списком Origin.
- WebSocket принимает токен через `Authorization: Bearer`; query-token оставлен только как совместимый fallback.
- WebSocket проверяет Origin, когда он передан браузером.
- Голосовые PCM-кадры и JPEG-кадры демонстрации экрана шифруются на клиенте через AES-256-GCM до отправки в WebSocket.
- Сервер ретранслирует только медиа-пакеты с префиксом зашифрованного формата.
- Клиент отбрасывает медиа-пакеты, которые не проходят проверку AES-GCM.

## Оставшиеся риски

- Текущий медиа-ключ выдается сервером авторизованным участникам канала. Это защищает от пассивного перехвата трафика и случайных логов сырого медиа, но не является строгим E2EE против полностью скомпрометированного сервера.
- Для доступа из сети нужен HTTPS/WSS через reverse proxy или TLS-терминацию. `ws://` допустим только для локальной разработки.
- Нет refresh-токенов, списка активных сессий и ручного отзыва конкретной сессии.
- Нет миграций БД, резервного копирования с шифрованием и политики удаления данных.
- Экран захватывается целиком. Перед production-нужна настройка выбора окна/монитора и заметное предупреждение перед началом трансляции.

## Следующий обязательный этап

- Ввести настоящий E2EE-дизайн для медиа: клиентские ключевые пары, обмен ephemeral-ключами, проверка отпечатков участников, ротация ключей при входе/выходе участника.
- Перевести production-запуск на HTTPS/WSS, закрыть прямой доступ к backend без TLS.
- Добавить журнал активных сессий, отзыв токенов, блокировку пользователя и аудит административных действий.
