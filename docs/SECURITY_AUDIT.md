# Аудит безопасности

Дата: 2026-08-17 (обновлено 2026-08-18)

## Закрыто в текущей версии

- Пароли хэшируются через Argon2.
- Access-токены подписываются HMAC-SHA256, имеют срок жизни и становятся недействительными после смены пароля.
- REST-запросы ограничены по размеру, входы и смена пароля защищены rate limit.
- Сервер требует явный `VOICECHAT_SECRET_KEY` и не стартует с примерным dev-секретом.
- HTTP-ответы получают базовые security headers.
- CORS отключен по умолчанию и включается только явным списком Origin.
- WebSocket принимает токен через `Authorization: Bearer`; query-token оставлен только как совместимый fallback.
- WebSocket проверяет Origin, когда он передан браузером.
- Клиенты генерируют локальные X25519 identity keys. На сервер отправляется только public key и его отпечаток.
- Медиа-ключ отправителя генерируется на клиенте и публикуется на сервере только в AES-GCM конвертах, зашифрованных через X25519/HKDF для public key конкретных участников.
- Голосовые PCM-кадры и JPEG-кадры демонстрации экрана шифруются на клиенте через AES-256-GCM до отправки в WebSocket.
- Сервер ретранслирует только медиа-пакеты с префиксом зашифрованного формата.
- Клиент отбрасывает медиа-пакеты, которые не проходят проверку AES-GCM.

## Исправлено 18.08.2026 (commit 03eb856)

### Replay protection для медиа-пакетов
- Класс `ReplayProtectedCrypto` встраивает sequence number в nonce каждого пакета
- Получатель проверяет что seq > последнего полученного, отбрасывая старые пакеты
- Nonce: 8 байт случайных + 4 байта sequence number (итого 12 байт, соответствует NIST SP 800-38D)

### Key rotation для sender keys
- Sender keys инвалидируются через 30 минут (константа `SENDER_KEY_TTL_SECONDS`)
- Фоновая очистка каждые 5 минут удаляет истёкшие записи
- Метод `invalidate_channel_keys()` принудительно инвалидирует все ключи канала

### AAD привязка к channel_id (протокол v2)
- Функция `make_voice_aad(channel_id, sender_id, recipient_id)` создаёт уникальный AAD
- Предотвращает пересылку зашифрованных кадров между каналами и парами

### Шифрование settings файла
- Опциональное шифрование E2EE приватных ключей через AES-GCM + PBKDF2HMAC (480,000 итераций)
- Мастер-ключ: `PRIVATE_VOICECHAT_MASTER_KEY` env или `master_password` в client_config.json

### Rate limiting для WebSocket
- Voice WebSocket: 5 подключений/мин с одного IP
- Screen share WebSocket: 5 подключений/мин с одного IP
- Создание пользователей: 10/мин с одного IP

## Оставшиеся риски

### КРИТИЧЕСКИЕ:

1. **MITM через подмену public key (HIGH)**
   - Сервер принимает любой public key без аутентификации
   - Злоумышленник с компрометированным сервером может подменить ключ
   - **Рекомендация:** UI проверки отпечатков + pin-сравнение между участниками

2. **Хранение private key без OS-level защиты (HIGH)**
   - На Windows используется только `os.chmod(0o600)`, NTFS ACLs могут не сработать
   - Ключ хранится в открытом JSON файле
   - **Рекомендация:** Использовать Windows DPAPI (`cryptography.fernet` с `win32_crypto`) или Credential Manager

### СРЕДНИЕ:

3. **Replay protection не работает между процессами (MEDIUM)**
   - Каждый вызов `encrypt_frame`/`decrypt_frame` создаёт новый объект с `_last_seq = 0`
   - Защита работает только внутри одного экземпляра клиента
   - **Рекомендация:** Использовать глобальные счётчики или персистентное хранилище

4. **Нет проверки отпечатков в UI (MEDIUM)**
   - Участники не могут verify что public key подлинный
   - **Рекомендация:** Добавить UI для сравнения отпечатков + предупреждение при смене ключа

5. **Отсутствует HTTPS/WSS принудительно (MEDIUM)**
   - `ws://` допустим для локальной разработки, но нет явного блокирования в production
   - **Рекомендация:** Добавить конфиг-флаг `FORCE_TLS=true` для production

6. **Нет refresh-токенов и отзыва сессий (MEDIUM)**
   - Токен живёт пока не истечёт (настраивается)
   - Нет способа отозвать конкретную сессию
   - **Рекомендация:** Добавить refresh tokens + session store с ручным отзывом

7. **Нет миграций БД и бэкапов (MEDIUM)**
   - База данных SQLite без шифрования на диске
   - **Рекомендация:** Добавить WAL mode, шифрование базы, cron бэкапы

### НИЗКИЕ:

8. **Хранение sender keys в памяти сервера без лимита (LOW-MEDIUM)**
   - `E2EEState` хранит все ключи в памяти, растёт бесконечно
   - TTL помогает но не предотвращает рост при активной работе
   - **Рекомендация:** Добавить max entries per channel + LRU eviction

9. **screen_relay не проверяет право трансляции (LOW)**
   - Сервер принимает фреймы от любого подключённого к WebSocket
   - Нет проверки `can_send` внутри broadcast loop
   - **Рекомендация:** Добавить флаг `is_sender` при подключении

10. **Зависимости — проверка на CVE (LOW)**
    - Не запущен `pip-audit` для проверки на известные уязвимости
    - **Рекомендация:** Запустить `pip-audit` в CI/CD пайплайне
